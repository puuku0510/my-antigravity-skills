# スライド素材収集スキル v3

## 概要
台本（MD / CSV / スプレッドシート）を読み込み、各セクションに対応する**参考素材のスクリーンショット**を20〜30枚収集する独立スキル。
pptx-skillとは完全に独立しており、素材収集のみを行う。

> [!IMPORTANT]
> このスキルは**スライド生成はしない**。素材の収集と整理だけを行い、保存先に保存する。
> スライド生成は `pptx-skill` で別途実行する。

- **保存先**: `C:\Users\keima\openclaw\slide-work\sources\`
- **Obsidian Vault（`C:\KEI IWASAKI\`）には絶対に保存しない**

## 🚨 ブラウザ安全ルール（最重要・絶対厳守）

> [!CAUTION]
> **このルールに違反するとPCがフリーズし、けいちゃんの作業が全部中断される。**
> **再起動が必要になり、進行中の全作業が失われる。絶対厳守。**

### ルール1: 1セッション = 最大2枚のスクショ
- `browser_subagent` の1回の呼び出しで、**最大2枚のスクショしか撮らない**
- 1枚のスクショフロー = 検索 → サイト遷移 → スクショ保存
- 2枚取ったら、**必ずreturnして** browser_subagentセッションを終了する
- 次の2枚は新しいbrowser_subagent呼び出しで行う

### ルール2: browser_subagentのTaskには必ず「終了条件」を明記
- 悪い例: 「バフェットの自宅のスクショを撮って」
- 良い例: 「以下の2枚のスクショを撮ったら即座にreturnしてください: (1) ... (2) ...。2枚撮り終わったら結果を報告してreturnすること。」
- **「完了したらreturn」を必ずTask文に含める**

### ルール3: read_url_contentを第一選択にする
- URLの存在確認、コンテンツの確認は `read_url_content` ツールで行う
- ブラウザは**スクショを撮る瞬間だけ**使う
- 例: まず `read_url_content` でページが存在することを確認 → 存在すれば `browser_subagent` でスクショ

### ルール4: 重いページの回避
- 動画自動再生ページは避ける
- 大量の高解像度画像ギャラリーは避ける
- ページが読み込まれるまでの待機は最大10秒。10秒以内にロードされなければスキップ
- Amazon、YouTube等の重いサイトでは、目的のコンテンツだけに集中し余計な操作をしない

### ルール5: バッチ間の確認
- 2枚のスクショを撮ったら、**成果を確認してから**次のバッチに進む
- エラーが発生した場合は無理にリトライせず、スキップして次に進む

## 📊 ソースバランスルール（50-30-20）

> [!IMPORTANT]
> **台本の内容に関係なく、以下の重み付けでソースタイプを配分する。**
> どんな台本でもWikipedia・場所・ブランドは出てくるが、放置すると全体の50%以上を占めてしまう。
> 意図的にTier 1を優先することで、視覚的バリエーションと情報密度を確保する。

### 優先順位

| Tier | 重み | ソースタイプ | 具体例 |
|------|------|-------------|--------|
| **Tier 1** | **50%** | グラフ・チャート・データ + X投稿 | 株価チャート、統計グラフ、研究機関レポート、有識者ツイート、バズ投稿 |
| **Tier 2** | **30%** | ニュース記事 | CNBC、Bloomberg、NHK、日経等の報道ページ |
| **Tier 3** | **20%** | Wikipedia・場所・ブランド等 | 人物Wiki、風景写真、公式サイト、書籍表紙 |

### 適用ルール

1. **台本を読んでコンテンツカテゴリを分類する**
   - 人物紹介・伝記 → Wikipedia候補
   - 数値・統計・推移 → チャート/グラフ候補
   - 事件・発表・ニュース → ニュース記事候補
   - 名言・世論・反応 → X投稿候補
   - 商品・ブランド → 公式サイト候補

2. **カテゴリ数を50-30-20で重み付けする**
   - 25枚収集する場合: Tier 1 = 12枚、Tier 2 = 8枚、Tier 3 = 5枚
   - 20枚の場合: Tier 1 = 10枚、Tier 2 = 6枚、Tier 3 = 4枚

3. **Tier 3がキャップを超えたら代替する**
   - 人物紹介が5箇所あっても → Wikipedia肖像は**2-3枚まで**、残りはニュース記事やX投稿で代替
   - 場所が3箇所出ても → 場所のスクショは**2枚まで**、残りはその場所に関するニュースで代替
   - 例: 「バフェットの自宅」→ Wiki写真 + 「バフェットの質素な生活」に言及したXポストで補完

4. **Tier 1の内訳バランス**
   - チャート/グラフとX投稿は概ね半々を目指す
   - 台本にデータ言及が多ければチャート寄り、意見・反応が多ければX寄りに調整

## 🚫 絶対禁止事項

> [!CAUTION]
> **以下のスクショは絶対に撮らない。1枚でもあったら全やり直し。**

### 1. 検索結果画面の禁止
- ❌ Google検索結果ページをそのままスクショ
- ❌ Google画像検索の一覧画面をそのままスクショ
- ❌ 「AI Overview」や「ナレッジパネル」だけのスクショ
- ✅ **必ず検索結果からリンク先のサイトに入って、そのページのコンテンツをスクショする**

### 2. 見切れ・フレーミング不良の禁止
- ❌ グラフや図表が途中で切れている
- ❌ 記事タイトルが見えない
- ❌ 重要な情報が画面外に切れている
- ❌ ポップアップやバナーが被っている
- ✅ **スライドに貼ったときに「何の画像か」が一目でわかるフレーミングで撮る**

### 3. 無理な収集の禁止
- ❌ 見つからない素材を無理やり代替品で埋める
- ❌ 品質の低いスクショで枚数を稼ぐ
- ✅ **見つからなかったらスキップする。20枚の高品質 > 30枚の低品質**

## スクショ品質基準（フレーミングルール）

> [!IMPORTANT]
> **「このスクショをそのまま16:9のスライドに貼って意味が通じるか？」が判断基準。**

### Webサイト・ニュース記事
1. **検索→リンク先に遷移→記事ページでスクショ**（検索結果では撮らない）
2. 記事の**見出し + リード文 + メイン画像**が入るようにフレーミング
3. 広告・サイドバー・Cookie同意バナーは閉じてから撮影
4. スクロール位置を調整して、必要な情報が**中央**に来るようにする

### グラフ・チャート・データ
1. グラフ全体が**見切れずに収まる**範囲でスクショ
2. 軸ラベル・凡例・タイトルが全て読める状態
3. データソースのサイトに直接アクセスして撮る（画像検索経由は不可）

### Wikipedia
1. 記事トップの**インフォボックス（人物写真＋基本情報）**を撮るのが基本
2. 特定セクションの場合は、**セクション見出し + 本文数行**が入るように
3. 目次や他のセクションは入れない

### 書籍表紙
1. Amazonの商品ページに入って、**表紙画像を拡大表示**してスクショ
2. 書籍タイトル・著者名が読める大きさ
3. Amazon UIの余計な部分（レビュー、価格等）はできるだけ除外

### X投稿
1. **ツイート単独表示**（パーマリンクページ）でスクショ
2. タイムライン全体は不要
3. ツイート本文 + 投稿者名 + 日時が入ること

## ワークフロー（5ステップ）

### ① トリガー
「素材集めて」「ソース収集して」「スクショ取ってきて」等で起動。

### ② 台本読み込み＋セクション分割
台本を読み込み、セクション（P0, P1, P2…等、またはCSVのセクション列）に分割する。

### ③ 収集計画を立てる（必須）
各セクションから**何を検索するか**を一覧にして提示。

```
素材収集計画（25枚）：
※ 50-30-20ルール適用: Tier1=12枚, Tier2=8枚, Tier3=5枚

セクション「欲望のコントロール」（6枚）
  #01 [chart] CEO報酬の推移グラフ（EPI公式レポート）         ← Tier 1
  #02 [x]     バフェットの質素な生活に関するバズツイート       ← Tier 1
  #03 [x]     CEO報酬格差に対する専門家のXポスト              ← Tier 1
  #04 [news]  バフェットの倹約生活ニュース記事（CNBC等）       ← Tier 2
  #05 [news]  マクドナルド朝食の話題を報じた記事              ← Tier 2
  #06 [web]   バフェットの自宅（Wikipedia）                   ← Tier 3（1枚のみ）

セクション「複利的思考」（6枚）
  #07 [chart] バークシャー株価チャート（MAX期間）              ← Tier 1
  #08 [chart] 複利の成長曲線グラフ                            ← Tier 1
  #09 [x]     複利・長期投資に関する投資家のXポスト            ← Tier 1
  #10 [news]  バフェットの投資哲学を解説するニュース記事       ← Tier 2
  #11 [news]  ベンジャミン・グレアムに関する記事              ← Tier 2
  #12 [web]   ピンボールマシン写真                            ← Tier 3
  ...
```

> [!CAUTION]
> **均等配分ルール**: 前半セクションに偏らないこと。
> セクション数で割って各セクション4〜6枚を目安にする。
> 最終セクション（まとめ/CTA）は1〜2枚で十分。
> **50-30-20ルールを各セクション内でも意識する。**

### ④ 承認
ディレクター: 「OK」or「#08は不要」「セクション3にもう1枚追加」等の修正指示。

### ⑤ 収集実行（バッチ方式・最重要）

> [!CAUTION]
> **必ずバッチ方式で実行する。1バッチ = 最大2枚。**
> **1つのbrowser_subagentセッションで3枚以上撮らない。**

#### バッチ実行フロー

```
収集計画: 25枚

バッチ1（#01, #02）
  → browser_subagent呼び出し（Task: 「#01と#02のスクショを撮ってreturn」）
  → 結果確認（成功/失敗を記録）

バッチ2（#03, #04）
  → browser_subagent呼び出し（Task: 「#03と#04のスクショを撮ってreturn」）
  → 結果確認

... 繰り返し ...

バッチ13（#25）
  → browser_subagent呼び出し
  → 結果確認
  → 全バッチ完了 → sources.json 生成
```

#### 1バッチの手順（browser_subagent内）
1. Google等で検索する
2. **検索結果からリンク先のサイトに遷移する**（ここ重要）
3. ページが完全に読み込まれるまで待つ（最大10秒）
4. ポップアップ・Cookie同意バナーを閉じる
5. スクロール位置を調整して、撮りたい範囲が画面内に収まるようにする
6. **フレーミングを確認してからスクショを撮る**
7. 2枚目も同様に実行
8. **2枚撮ったら即座にreturn**

#### 見つからなかった場合
- 3回検索しても良い素材が見つからない → **スキップして次に進む**
- 最終的な枚数が計画より少なくなってもOK

**ファイル名:** `{連番2桁}_{カテゴリ}_{説明}.png`（例: `01_web_buffett_house.png`）

## 枚数ガイドライン

| 台本の長さ | 推奨枚数 |
|-----------|---------|
| 〜30カット（短尺） | 15〜20枚 |
| 30〜60カット（中尺） | 20〜25枚 |
| 60カット〜（長尺） | 25〜30枚 |

> [!IMPORTANT]
> **枚数は目安であり上限ではない。品質が確保できなければ減らしてよい。**
> 20枚の高品質スクショ >>> 30枚の低品質スクショ

## 注意事項

- **著作権**: スクショは動画内で「引用」として使用する前提。出典URLを必ず `sources.json` に記録する
- **X投稿**: 公開ツイートのみ対象。鍵アカウントのスクショは取らない
- **重複回避**: 同じサイト/同じツイートを複数枚取らない
- **鮮度**: ニュース記事は可能な限り直近1年以内のものを優先
- **保存先**: `C:\Users\keima\openclaw\slide-work\sources\`（Vault外。Obsidian Vaultには入れない）
