# X投稿スクリーンショット自動収集スキル

X（旧Twitter）上の有益な投稿やバズツイートのURLを受け取り、ブラウザ（ヘッドレス）を自動操作して、ツイート単体の綺麗なスクリーンショットを自動で収集・保存するSkillです。

---

## 🚨 ブラウザ安全ルール（PCフリーズ防止・絶対厳守）

ブラウザの自動操作（スクショ撮影）はメモリとCPUを大量に消費するため、**以下のフリーズ防止ルールを必ず厳守してください。**

### ルール1: 1セッション = 最大2枚 of スクショ
* 1回のブラウザセッション（`browser_subagent` などの呼び出し）で撮影・保存するのは**最大2枚まで**とします。
* 3枚目以降を撮影する場合は、必ず一度ブラウザセッションを終了し（`return`）、新しいセッションを立ち上げ直して次の2枚を撮影してください。

### ルール2: セッションの「終了条件」を必ず明記
* ブラウザ自動操作 of 指示（Task）を出す際は、必ず以下のように「終了条件」を明記してください。
  > **「指定された2枚のスクショを撮影したら、即座に結果を報告してreturn（セッション終了）してください。」**

### ルール3: ページの読み込み待機は最大10秒
* ネットワーク遅延やX側の読み込み遅延に備え、ページの読み込み待機時間は最大10秒とします。10秒以内にツイートが表示されない場合は、そのURLをスキップして次に進んでください。

## 📸 スクショ品質基準（フレーミングルール）

資料やスライドに貼り付けたときに、「誰が何を発言しているか」が一目でわかる状態で撮影します。

1. **パーマリンク表示での撮影**
   * 必ずツイートの個別URL（パーマリンク）にアクセスして撮影してください。タイムライン全体や検索結果の画面のまま撮影するのは禁止です。
2. **要素の網羅**
   * **「投稿者のアバターアイコン＋ユーザー名＋ID（@ハンドル）」「ツイート本文」「投稿日時」**がすべて画面内に綺麗に収まり、文字が見切れていない状態で撮影します。
3. **不要なバナーの除外**
   * ログイン誘導バナー、Cookie同意ポップアップ、サイドバーなどの不要な表示がツイートの上に被っている場合は、自動スクロールで位置を調整するか、バナーを閉じる処理を行ってから撮影します。

## 🛠️ ワークフロー

### ① URLリストの受け取り
ユーザーからXの投稿URL（または台本内に記載されたXの参考リンク）を受け取ります。

### ② 収集計画の提示
撮影するファイル名と順番の一覧を提示し、確認を得ます。
* **出力ファイル名規則**: `[連番2桁]_x_[投稿者ID].png`（例: `01_x_buffett_code.png`）

### ③ バッチ実行（最大2枚ずつ）
安全ルールに従い、2枚ごとにブラウザセッションを起動してスクショを撮影します。
* **保存先**: `./output/x-screenshots/` (カレントディレクトリ内の出力フォルダ)

### ④ 結果の出力
すべてのスクショを撮影し終えたら、以下の構成でメタデータJSONファイル（`sources.json`）を出力します。

```json
[
  {
    "id": 1,
    "filename": "01_x_buffett_code.png",
    "url": "https://x.com/buffett_code/status/...",
    "author": "buffett_code",
    "capturedAt": "2026-05-30T19:20:00Z"
  }
]
```

## ⚙️ トラブルシューティング

* **Xのログイン画面に阻まれる場合**:
  * 閲覧制限によりログイン画面が表示されてしまう場合は、無理に撮影を繰り返さず、スキップするか、読み取り可能なパブリックパーマリンクであることを確認してください。
